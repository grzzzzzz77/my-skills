# 简历改写范式（craft 指南 · 两 track 共用）

> 用途：① 给简历诊断"怎么改"的建议提供**可照做的范式**；② 在诊断模块产出 **before→after 改写示范**时遵循的标准。
> 来源：提炼自一份"国企/央企/大厂网申增强版"简历改写器提示词，转化为我们诊断 / 建议用的 craft 知识。
> ⚠️ 本文件是"怎么写好一条经历"的方法，**不是输出格式**——我们的产物始终是**分析报告**，不是 JSON 简历，
> 也不替用户整份代写。

## 0. 真实性边界（最高优先级，压倒一切技巧）
- **只能基于用户已提供的信息做逻辑补充 / 流程描述，绝不虚构经历、公司、项目、数据、组织。**
- **扩写 ≠ 编造**：可把"负责测试"扩成"负责 XX 模块的功能与回归测试、用 XX 工具定位问题"——
  前提是这些是其**真实做过**的；不能凭空加一段没发生的事。
- **缺数字不许编**：用户没给量化结果时，改写里用**占位提示**让他自己填，如
  "（补充具体数字：如处理缺陷数 / 覆盖率 / 效率提升 X%）"，**绝不替他编一个数字**。
  这是与原"可写量化成果"改写器最关键的区别——**我们宁可留占位，也不替用户造假**。

## 1. STAR 落地模板（经历类描述：实习 / 项目 / 校园）
按"情境→任务→行动→成果"四段展开，但**禁止出现 "S/T/A/R"、"情境""任务"等任何标签词**，读起来是自然段落：
- 结构：[情境背景]；[任务目标]；[一句完整连贯的行动长句]；[量化成果]。
- **行动部分写成一句连贯长句、不拆成多点**，体现思路与方法。
- 量化成果优先用真实数字；没有就留占位（见 §0）。
- 篇幅作**方向性参考**（一条经历约 3-5 句，不过短也别注水）；**不设硬性字数指标**——
  原提示词的"250-400 字"是为喂平台，我们不强制，避免为凑字数逼出废话。

## 2. 专业动词 + 去口语化 + 格式
- 专业动词开头：主导 / 负责 / 设计 / 实现 / 搭建 / 优化 / 推动 / 完成 / 分析 / 协调 / 执行…
- 去口语化与流水账："我当时帮忙弄了一下"→"参与 XX 的 XX 工作"。
- timeRange 统一 `YYYY.MM - YYYY.MM`；联系方式等保持规范一致。

## 3. 加粗（让 HR 三秒看到亮点）
- **该加粗**：专业技能 / 工具 / 框架、核心职责 / 独立负责 / 复杂问题解决、量化数据 / 成果、奖学金 / 竞赛 / 证书 / 荣誉。
- **不该加粗**：参与 / 协助 / 负责 这类普通叙述虚词，以及整句长段。
- 密度作方向性参考：一段实习 / 项目几处亮点即可，**不为凑加粗而编造或硬标**。
- 注：我们报告里用标准 `**加粗**`（docx 会渲染），不用平台专属的三星 `***` 写法。

## 4. 技能 / 个人优势写法
- **技能**：类别可加粗，描述用完整句 + **应用场景**（"掌握 XX，曾用于 XX 项目的 XX"），不堆名词。
- **个人优势**：每点三段式——**能力来源 + 实际经验 / 成果 + 岗位匹配价值**；核心能力加粗，不编号、不空喊。

## 5. 产出 before→after 改写示范的方法（用在诊断模块）
当报告点出某条经历写得弱时，给一条**改写示范**，让用户直接照搬思路：
1. 先贴用户**原文**（"原文：…"）。
2. 再给**改写后**（"建议改为：…"），套 §1 模板、§2 动词、§3 加粗。
3. 缺的量化按 §0 留占位，并用一句话说明**改了什么、为什么更好**。
- 一份报告给 **1 条**（弱简历可给 2 条）最有代表性的示范即可；
  **不要逐条改写整份简历**——那会喧宾夺主、也容易滑向"代写"，偏离我们"诊断 + 教练"的定位。

## 雇主类型微调（详见 `employer-type-strategy.md`）
- 国央企 / 网申：更强调规整、量化、加粗亮点、关键词齐全（过 ATS）。
- 互联网大厂：强调项目深度与技术量化。
- 外企：示范可提示"另准备英文版、突出 leadership / 影响力"。
