# 求职就业评估报告生成

根据用户的简历和求职需求，融合三类数据源——**简历内容** + **沉淀的行业知识**（`references/`）
+ **实时市场数据**（Web Search）——生成一份个性化的就业评估报告。报告既是对用户的专业服务
交付物，也是后续付费转化的入口。

## 角色说明（重要）

- **本 skill 的使用者是公司的「服务老师」**，不是学生本人。服务老师会先从学生（用户）
  那里收集简历和求职需求，再把这些信息转交给本 Agent。
- 因此 Agent 的所有交互对象是**服务老师**：信息确认、追问补充信息，都是面向服务老师进行的。
- **报告的最终读者**是学生本人（部分情况下还有家长）。因此报告正文的语气、话术面向学生，
  遵循 `references/report-style-guide.md`；而流程中的对话（确认、追问）面向服务老师，
  可以更直接、专业、简洁。

## 总体流程

1. **信息采集**：从用户简历和对话中提取所需字段（见"信息采集指引 / 输入 Schema"）
2. **信息确认**：先向服务老师复述已提取到的关键信息，并主动追问"还有信息没有补充吗？"
   **必须等到服务老师明确表示没有额外信息后，才能进入后续步骤**（见"信息确认关卡"）
2.5 **学历路由**：根据 `degree` 判断走「本科 +」还是「专科 / 高职」track，决定加载哪套知识库与
   报告结构模板（见"§1.6 学历路由"）。**这一步决定了后面所有模块的口径，必须先分流再加载。**
3. **知识加载**：读取 `references/` 下**对应 track** 的知识库文件
4. **实时搜索**：执行 3-5 次 Web Search 获取市场、政策与方向数据（搜索 0/4 视情况触发）
5. **报告生成**：按 `templates/report-structure.md` 的模块结构逐模块生成
6. **输出交付**：**最终产物必须是 Word(.docx)**。先把报告写成 Markdown 中间稿，再调用
   `scripts/build_docx.py` 转成带公司 logo 的 .docx 交给服务老师（见"5. 输出格式"）

> ⚠️ **不要在服务老师首次提交简历和需求后就直接生成报告**。必须先完成"信息确认关卡"，
> 由服务老师确认信息齐全后再开始。

> 核心原则贯穿全流程：**有数据用数据，没数据就降级兜底，绝不编造**。学校分档、政策数字、
> 薪资区间这类信息，搜不到 / 查不到时使用通用表述或提示用户自行核验，不得虚构。

## 1. 信息采集指引

从**服务老师提交的简历和需求信息**中提取以下字段。如果缺少某些字段，可以向**服务老师**
追问（请服务老师向用户补充收集），但**追问一次不超过 3 个问题**，优先基于已有信息生成报告。

> 简历可能以多种形态提交（纯文本/粘贴内容、PDF、Word、截图/图片等）。无需特殊适配，
> 直接读取其中的简历信息即可。

### 输入 Schema

**必填字段（缺少则报告无法生成）**：
- `school`：毕业院校
- `major`：专业
- `degree`：学历层次（**专科/高职 · 本科 · 硕士 · 博士**）。**决定走哪条报告 track**（见 §1.6 学历路由）
- `graduation_year`：毕业年份（如 2025）
- `target_city`：目标求职城市

> **专科 / 高职学生额外必填 `current_grade`（当前年级 / 是否应届）**：专科 track 的核心模块要判断
> "统招专升本还来不来得及"，这强依赖当前年级 + 咨询时间。简历只有毕业年份时可结合当前日期推算
> （多数 3 年制：毕业当年=大三/应届），不确定则在确认关卡向服务老师核实。
>
> **专科 / 高职学生额外建议确认 `zsb_status`（是否已报考本年度统招专升本 / 在等录取结果）**：
> 简历通常**不会写**这条，但它直接决定模块 3 的方向——若学生其实已报考、正在等结果，报告就不该按
> "以就业为主"写，而要按"准备入学本科"安排。**尤其当学生正值毕业季、本省今年专升本考试已结束时
> （此时只看简历会默认其放弃了升学）**，务必在确认关卡请服务老师向学生问一句。默认未报考时，
> 报告以就业为主线，并在模块 3 留一句"若已报考在等结果请告知"的兜底。

**从简历中提取（有则用，无则标注缺失）**：
- `gpa`：GPA 或排名
- `tech_stack`：技术栈/技能列表
- `projects`：项目经历（名称、简述、技术栈、个人角色、成果）
- `internships`：实习经历（公司、岗位、时长、工作内容）
- `competitions`：竞赛/证书/论文
- `student_work`：社团/学生干部经历

**用户补充（如未从简历获取则询问，受 3 问上限约束）**：
- `target_direction`：期望岗位方向（如：后端开发/前端/算法/测试/不确定）
- `salary_expectation`：期望薪资范围
- `job_status`：当前求职状态（未开始/已投递无回音/面试中/已拿 offer 在比较）
- `concerns`：最担心的问题或最想了解的方面
- `hometown`：户籍 / 生源地（省市即可）。**影响政策福利的适用性**——落户补贴、人才引进等
  常区分本地 / 外地生源。缺失时模块 5 只做通用提醒、不替学生判定能否申领（见搜索 2 与模块 5）

## 1.5 信息确认关卡（生成前必经）

完成信息采集后，**不要立即进入知识加载和报告生成**。先向**服务老师**做一次信息确认：

1. **复述已掌握的信息**：用简洁的列表向服务老师回显从简历和需求中提取到的关键字段
   （必填字段 + 已获取的选填/补充字段），让服务老师一眼核对"系统理解到的学生情况"是否准确。
2. **指出缺失或不确定的项**：如有必填字段缺失或某些信息模糊，在此一并提示服务老师。
   - 若 `hometown`（户籍/生源地）缺失，提示服务老师："如能补充学生户籍/生源地，政策福利部分能判断得更准
     （落户、人才引进等常区分本地/外地生源）；不补也可生成，但政策只能做通用提醒。"
   - **（仅专科 / 高职 track）**确认 `zsb_status`：提示服务老师"麻烦向学生确认一下——
     **是否已经报考本年度统招专升本、或正在等录取结果？** 这决定报告是按'以就业为主'还是'准备入学本科'来写。
     **若学生正值毕业季、本省今年考试已结束**，仅凭简历会默认其放弃升学，所以这一句尤其要问。"
3. **主动追问**：明确询问服务老师 **"还有信息没有补充吗？"**（例如学生的更多项目细节、
   实习经历、特别关注的方向或城市、特殊情况等，需要服务老师向学生补充收集的内容）。
4. **等待服务老师确认**：
   - 如果服务老师补充了新信息 → 更新已掌握的字段，**再次确认**，直到服务老师表示没有更多信息。
   - 只有当服务老师**明确表示没有额外信息**（如"没有了""可以了""开始吧"）后，
     才进入"知识加载 → 搜索 → 报告生成"。

> 这一步的目的：报告质量高度依赖输入完整度，提前一轮确认能让服务老师有机会补全从学生处
> 收集到但遗漏录入的信息，显著减少返工。**这是硬性流程，不可跳过。**

## 1.6 学历路由（本科 + / 专科 分流）

信息确认完成后、加载知识库前，**先按 `degree` 分流**。专科 / 高职与本科是**赛道差异、不是程度差异**
（院校体系、岗位性质、简历重心都不同，且专科多一条"专升本 vs 直接就业"的主线），两套逻辑分开走、不混用。

| 学历层次 | 走哪条 track | 报告结构模板 | 院校 / 简历知识库 |
|---|---|---|---|
| **专科 / 高职** | **vocational track** | `templates/report-structure-vocational.md`（8 模块） | `references/vocational-schools.md` + `references/vocational-resume-checklist.md` + `references/vocational-zhuanshengben.md`（专升本沉淀框架） |
| 本科 / 硕士 / 博士 | 本科 + track（现有） | `templates/report-structure.md`（7 模块） | `references/school-tiers.md` + `references/resume-checklist.md` |

- **共用（两条 track 都加载）**：`references/report-style-guide.md`（语气话术）、
  `references/major-career-map.md`（专业→岗位的运行时搜索方法）、`references/service-offerings.md`（最后模块的服务承接素材）、
  检索执行机制（三层）、信息确认关卡、输出格式（docx）。
- **专科 track 关键点**：核心是新增的"升学 vs 就业 路径研判"模块，立场为
  **建议"升学 + 就业并行、用就业给升学打保底"**；并要结合**当前年级 + 咨询时间 + 本省专升本考试时间（搜索 5）**
  判断升学可行性。细节见 `report-structure-vocational.md`。
- **边界 case**（在确认关卡向服务老师核实，别猜）：
  - 校名含"职业技术大学"等但发**本科**文凭 = **职业本科，属本科 track**，不是专科。
  - "专升本在读 / 专科 + 自考本科" = 已在或已完成升学，按其**当前实际就读层次**判断走哪条 track，
    并在画像里如实说明背景。
  - ⚠️ **简历有多段教育经历时（如专科 + 本科），`degree` 取"当前/最高在读或已获"层次**——
    专升本成功的学生 `degree=本科`、走本科 track，**专科段作为加分背景写进模块 2**（体现学习能力、第一学历提升）；
    若专升本是全日制统招还是自考/成考无法确定（影响第一学历表述），在确认关卡向服务老师核实。

> 下文"§2 知识加载""§3 搜索""§4 报告生成"中提到的 `school-tiers.md`、`resume-checklist.md`、
> `report-structure.md` 均为**本科 + track** 的默认文件；走专科 track 时，按上表替换为 vocational 对应文件
> 与 8 模块结构，其余流程（搜索机制、确认关卡、docx 输出）完全一致。

## 2. 知识加载

> 下面列的是**本科 + track 默认文件**。走专科 / 高职 track 时，按 §1.6 学历路由把 `school-tiers.md`、
> `resume-checklist.md` 替换为 `vocational-schools.md`、`vocational-resume-checklist.md`；其余共用。

读取以下文件，作为报告对应模块的素材：

- `references/school-tiers.md` → 查找用户学校所在的梯队（模块 2）
- `references/major-career-map.md` → **不是数据表**，而是「专业→岗位方向」的搜索方法与
  输出结构指引。专业种类繁多，**具体的专业对口方向、技能要求、薪资在运行时通过搜索获取
  （见搜索 0），本文件只规定怎么搜、产出哪些维度、格式长什么样**（模块 2、模块 3、模块 6）
- `references/resume-checklist.md` → 用于简历诊断（模块 4）
- `references/report-style-guide.md` → 控制报告语气和话术（贯穿全报告）
- `references/service-offerings.md` → 最后一个模块（本科 7 / 专科 8）的服务承接素材：
  两档服务方案 + "自然、不像广告"的写法（不堆清单、不放价目表，报价交服务老师）。**两条 track 共用**

如果学校不在分档表中，使用通用描述，**不要编造分档信息**。
专业方向不在静态示例中属正常情况——按 `major-career-map.md` 的方法**运行时搜索**即可。

## 3. 实时搜索策略

生成报告前执行以下搜索。下方"搜索 0~4"定义的是**查什么**（查询词与用途）；
具体**怎么查**，统一遵循「检索执行机制（三层）」——优先内置搜索，质量不行就回退抓官方页面，
仍拿不到再走降级。三者配合，确保在不同运行环境下都能尽量拿到真实数据、绝不编造。

> **先分清"沉淀"还是"实时查"，别什么都现查**：
> - **稳定的公开 / 官方 / 权威事实**（如专升本的报考资格、时间规律、与自考成考的区别）查证一次后
>   **沉淀进 `references/` 知识库直接复用**（如 `vocational-zhuanshengben.md`），运行时不重复查。
> - **逐城市 / 逐专业 / 逐年变化的动态信息**（具体城市薪资政策、某专业对口方向、本省当年专升本精确节点）
>   **才走下面的搜索**。沉淀的不重复查、会变的不当成不变——既省力又不把过时信息写成"事实"。

### 搜索 0（前置）：专业对口岗位方向
- 触发条件：用户**未明确 target_direction**，或其专业不在 `major-career-map.md` 的格式示例中
- 查询：`{major} 应届生 对口岗位方向 就业方向 核心技能要求`
- 用途：动态获取该专业可选的 2-3 个主流岗位方向及其技能要求（替代硬编码的专业映射表）
- 处理：按 `major-career-map.md` 规定的输出维度（核心技能/进阶技能/市场需求/薪资/适合人群）
  整理搜索结果；**先于搜索 1 执行**，因为搜索 1 的"方向"参数依赖本步结果
- 填充模块：模块 2（专业匹配度）、模块 3（方向推荐）、模块 6（技能补强）

### 搜索 1：市场与薪资
- 查询：`{target_city} {target_direction 或 major} 就业 薪资 招聘 2026`
- 用途：获取目标城市该方向的薪资区间、岗位供需情况、行业趋势
- 填充模块：模块 3（目标市场分析）

### 搜索 2：政策信息
- 查询：`{target_city} 应届生 就业补贴 落户政策 2026`
- 用途：获取最新的应届生补贴金额、落户条件、人才政策
- **生源地处理**：补贴 / 落户 / 人才引进常区分本地与外地生源。
  - 已知 `hometown` 且与 `target_city` 不同 → 补一条查询 `{target_city} 非本地生源 应届生 落户 人才引进 补贴 2026`，
    分别整理"本地 / 外地生源各自适用什么"
  - 未知 `hometown` → **不替学生判定能否申领**，只罗列政策并标注"是否适用取决于户籍 / 生源地，请自行核验"
- 填充模块：模块 5（政策福利）

### 搜索 3：产业动态
- 查询：`{target_city} {行业关键词} 产业 招聘趋势 2026`
- 用途：获取目标城市产业发展方向、哪些企业在扩招
- 填充模块：模块 3（目标市场分析）

### 搜索 4（可选）：学校就业数据
- 查询：`{school} 就业质量报告 毕业生去向`
- 用途：如果能搜到该校的就业质量报告，作为分析素材
- 填充模块：模块 2（竞争力评估）

### 搜索 5（仅专科 / 高职 track）：专升本**动态信息**
- 触发条件：**走 vocational track 时执行**（本科 + track 不需要）
- ⚠️ **先看知识库，再决定查什么**：专升本的通用框架（仅应届可考 / 一次机会 / 报名早于考试的时间规律 /
  与自考成考区别）**已沉淀在 `references/vocational-zhuanshengben.md`，是稳定权威事实、直接用、不要再查**。
  搜索 5 **只查逐省逐年逐专业变化的动态信息**：
  - 查询：`{省份} 统招专升本 {当前/次年年份} 报名时间 考试时间`（取**本省当年精确节点**）、
    `{省份} 专升本 {当前年份} 政策 改革`（看当年有无扩招/资格调整）、必要时
    `{省份} {专业} 专升本 对口本科院校 报录比`（对口院校与竞争度）
- 用途：拿到本省**当年**的精确节点与竞争情况，配合知识库框架，供模块 3 判断"还来不来得及"、模块 7 排时间线
- 处理：**以搜到的本省官方最新公告（省教育考试院 / 教育厅）为准**；结合学生**当前年级 + 当前咨询日期**判断；
  **搜不到精确时间就提示"以本省教育考试院最新公告为准"并按年级给方向性判断，绝不编造日期**
- 填充模块：模块 3（升学 vs 就业 研判）、模块 7（行动时间线）

### 检索执行机制（三层）

上面每条搜索都按下面的顺序执行，前一层够用就停，不够再降到下一层：

**第 1 层 — 内置 WebSearch（首选）**
- 直接用 WebSearch 跑搜索 0~4 的查询词。
- ⚠️ 已知局限：WebSearch 可能是非中国大陆节点，查"城市政策 / 本地薪资"等中文本地信息时，
  结果常混入大量无关项（英文招聘、海外网站、广告），或只返回过时旧闻。
- **质量自检**：拿到结果后判断——是否命中目标城市/方向的中文本地信息？数字是否够新（贴近当前年份）？
  命中且新 → 采用，进入数据来源标注；**噪音多、过时或答非所问 → 进第 2 层**。

**第 2 层 — 抓取官方/本地站点（回退，针对中文本地数据）**
- 适用：政策（搜索 2）、本地薪资与产业（搜索 1/3）这类**强本地、强时效**的中文数据，第 1 层质量不行时。
- 方式：用 `curl` 经 Jina Reader 抓取页面正文（URL 中的中文需 percent-encode）：
  ```bash
  curl -s --max-time 30 "https://r.jina.ai/<目标页面URL>"
  ```
- **数据源优先级（按实测有效性排序，2026-06 真实测试验证）**：
  1. **垂直站直抓**——最有效。按数据类型选站：
     - 薪资 / 岗位供需 → 招聘聚合站（如**职友集 `jobui.com/salary/<城市>-<岗位>/`**），通常有结构化数字；
     - 政策 / 补贴 / 落户 → **当地人社局 / 政府官网（gov.cn）**、当地"本地宝"政务聚合站。
  2. **百度搜索结果页**——`https://r.jina.ai/https://www.baidu.com/s?wd=<编码查询>`。
     对中文政策类收录好、聚合摘要里常直接含关键数字，可据此再抓具体文章页核实。
  3. **Bing 搜索结果页**——`.../bing.com/search?q=...`。⚠️ 实测对中文本地查询噪音极重
     （常返回旅游、百科、海外结果），**仅在百度与垂直站都拿不到时才用，且需大力清洗**。
- 抓取后清洗：用 `grep` 滤掉导航/广告噪音（如 `民办|小学|健康证|绘本|旅游` 等无关词），保留含目标关键词的行。
- ⚠️ **清洗 ≠ 用窄关键词去"抽答案"**：grep 只用来**去噪**，判断有没有数据要**读正文**。
  实测教训：对"汉语言文学就业方向"用窄词 grep+计数，曾误判成"几乎没数据"，而实际百度正文里
  方向（教育/党政/媒体/企业）写得很全。**先把正文读出来再判断，别让窄 grep 把好数据滤没了。**
- 只采信能定位到**明确出处和时间**的内容；抓到的页面同样要做质量自检，不达标 → 进第 3 层。
- 说明：本层零额外依赖（只用 curl + 公网），可在分发后的环境运行。
  （本地若另装了 agent-reach 等更强检索工具，可作为开发期查证增强，但**不写入本 skill 的运行依赖**。）

**第 3 层 — 降级兜底（前两层都拿不到时）**
- 搜索无结果 / 结果不相关 → 该数据点**跳过，不编造**。
- 政策、薪资搜不到具体数字 → 用通用表述兜底（如"建议关注当地人社局官网获取最新政策"），
  并提示用户自行核验、给出官方查询渠道。
- 宁可少给一个数字，也不给一个编的数字。

### 数据来源标注（贯穿三层）
- 第 1/2 层搜索所得 → 标"**据公开信息**"，政策类加注"具体以官方最新公告为准"。
- 知识库中属经验沉淀的 → 标"**基于行业经验**"。
- `school-tiers.md` 中带排名/就业出处的判断（如偏弱 985）→ 标注其具体来源（如"**据软科/校友会排名**"）。
- **能给链接就给可点链接**：薪资/政策等数据，若搜索时拿到了来源页 URL，用 Markdown 链接写出处
  （如 `[职友集](https://www.jobui.com/salary/hangzhou-java/)`、人社局官网），方便学生自查、也更可信。
  **只写真实取得过的 URL，绝不编造链接**；没把握的就只写来源名 + 官方查询渠道名，不硬凑地址。

## 5. 输出格式

**最终交付物必须是 Word(.docx)，不是 Markdown。** 服务老师拿到的是可直接发给学生的 Word 文档。

生成流程（两步）：

1. **先写 Markdown 中间稿**——按模块把报告内容写成一个 `.md` 文件（便于你组织结构、也方便留档）。
   文件名：`{school}_{major}_{target_city}_就业评估报告.md`
2. **再转 .docx**——调用本 skill 自带的转换脚本：

   ```bash
   python3 scripts/build_docx.py "<报告.md>" "<同名.docx>"
   ```

   脚本会输出 `{school}_{major}_{target_city}_就业评估报告.docx`，**右上角自带"找北求职" logo**（页眉，每页都有）。
   转换完成后，把 **.docx** 交付给服务老师（.md 作为留档/可选）。

**为什么用这个脚本，不用 pandoc / textutil / python-docx：**
- 转换**只依赖 python3 标准库**（.docx 本质是装着 XML 的 zip，脚本用 `zipfile` 直接生成）。
  不需要联网安装、不依赖系统里"碰巧装了"的工具——**任何装了本 skill 的使用者都能转**，这是硬要求。
- logo 文件在 `assets/logo.png`，已随脚本嵌入页眉；脚本默认自动找它，无需手动传路径。

**报告 Markdown 的写法约束**（保证转换效果）：
- 标题用 `#` / `##` / `###`；正文用空行分段；强调用 `**加粗**` / `*斜体*`。
- 列表用 `- `；需要表格时用标准 Markdown 表格（`| … |` + `| --- |`），脚本会转成 Word 原生表格。
- 不要写 HTML、图片、代码块等模板里没有的元素（脚本不解析，会被忽略）。
- **不要在段首手动敲空格做缩进**——转换脚本会自动给正文段落加"首行缩进 2 字符"（标题/小标题/列表/引用不缩进）。
  手动加空格会和自动缩进叠加，反而错位。
