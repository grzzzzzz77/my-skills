# 专业 → 岗位方向：搜索方法与输出结构指引

> **本文件不是数据表，而是方法指引。**
> 我们服务的用户专业种类繁多，把每个专业的对口方向、技能、薪资硬编码进来既维护不动、也容易
> 过时失真。因此**专业对口方向在运行时通过搜索动态获取**（见 SKILL.md「搜索 0」），本文件
> 只规定三件事：① 怎么搜；② 每个方向要产出哪些维度；③ 输出格式长什么样（附一个示例）。

## 使用流程

1. **确定方向来源**：
   - 用户已明确 `target_direction` → 直接用，搜索时聚焦该方向的技能要求与市场情况。
   - 用户未确定方向 → 执行「搜索 0」，获取该专业的 2-3 个主流对口方向。
2. **结合用户技术栈做交集**：在搜索得到的候选方向中，优先推荐与用户已有技术栈/项目经验
   最匹配的 2-3 个，而不是罗列全部。
3. **按下方「输出维度」整理每个方向**，保证不同专业、不同方向的产出结构一致。
4. **标注数据来源**：搜索所得标"据公开招聘信息"；薪资等具体数字遵循 SKILL.md 的降级策略，
   搜不到不编造。

## 搜索建议（运行时）

- 专业有哪些对口方向：`{major} 应届生 对口岗位方向 就业方向`
- 某方向的技能要求：`{方向} 校招 岗位要求 核心技能 应届`
- 某方向的薪资：`{target_city} {方向} 应届生 薪资`（与 SKILL.md 搜索 1 复用）
- 若专业冷门/名称特殊：先搜该专业的典型就业去向，再就近归类到可搜索的岗位方向

## 输出维度（每个推荐方向都要覆盖）

每个岗位方向，整理为以下结构（数据以运行时搜索为准）：

- **核心技能**：入门该方向必须掌握的技术/工具
- **进阶技能**：拉开差距、面向中高级岗位的能力
- **市场需求**：供需概况（旺盛/稳定/竞争激烈/岗位偏少等），尽量有依据
- **薪资参考**：应届区间 + 几年后区间，标注城市与来源
- **适合人群**：什么特质/背景的同学适合该方向

## 输出格式示例（计算机类）

> ⚠️ 以下仅为**格式与颗粒度示例**，帮助理解每个方向该写成什么样。
> **其中的市场需求与薪资数字是示意性的，实际生成报告时必须用运行时搜索的最新数据替换，
> 不要直接照抄这里的数字。** 非计算机专业同理，按上述方法搜索后套用此格式。

### 后端开发
- 核心技能：Java/Go/Python, Spring Boot/Django, MySQL/PostgreSQL, Redis, 消息队列, Linux, Git
- 进阶技能：微服务架构, Docker/K8s, 分布式系统, 高并发
- 市场需求：需求量较大（以搜索结果为准）
- 薪资参考：（运行时按目标城市搜索填入）
- 适合人群：有后端项目经验、喜欢系统设计的同学

### 前端开发
- 核心技能：HTML/CSS/JavaScript, React/Vue, TypeScript, Webpack/Vite
- 进阶技能：Node.js, 小程序开发, 性能优化, 前端工程化
- 市场需求：需求较大（以搜索结果为准）
- 薪资参考：（运行时按目标城市搜索填入）
- 适合人群：有前端项目作品、对用户体验敏感的同学

### 算法/机器学习
- 核心技能：Python, PyTorch/TensorFlow, 数学基础(线代/概率/优化), 数据结构与算法
- 进阶技能：NLP/CV/推荐系统, 大模型微调, MLOps
- 市场需求：岗位相对少、竞争激烈、常要求硕士（以搜索结果为准）
- 薪资参考：（运行时按目标城市搜索填入）
- 适合人群：数学基础好、有论文或竞赛经历、硕士及以上

### 其他常见方向（测试开发 / DevOps / 数据开发等）
按同一格式处理：先搜该方向的核心/进阶技能、市场需求与薪资，再按「输出维度」整理。
不再在本文件中逐方向硬编码。
